# Managed macOS installer

Portal's installer is a user-level bootstrap, not a privileged package. This is deliberate: Hermes provider authentication is interactive and its gateway is a per-user launchd service. Running those steps from a root-owned `.pkg` postinstall script would put credentials and files under the wrong account.

## User flow

1. Open `Portal-Installer.dmg`.
2. Double-click **Set Up Portal.command**.
3. Complete the Hermes provider prompt.
4. Portal opens with `ws://127.0.0.1:8642/v1/ws` and the generated key prefilled.
5. Press **Connect**. Portal saves the URL and key in Keychain and deletes the temporary handoff.

The setup command is safe to rerun. It preserves an existing API key and asks the Hermes installer to update the managed fork checkout.

## Installed layout

| Component | Location |
|---|---|
| Portal app | `~/Applications/Portal.app` |
| Hermes fork checkout | `~/Library/Application Support/Portal/hermes-agent` |
| Hermes profile/configuration | `~/Library/Application Support/Portal/hermes-home` |
| Temporary Portal handoff | `~/Library/Application Support/Portal/bootstrap.json` |
| Gateway service | Per-user launchd agent generated by `hermes gateway install` |

The custom `HERMES_HOME` gives this gateway a profile-specific launchd label, so it does not replace a user's default Hermes service.

## Security properties

- The setup command refuses to run as root and never invokes `sudo`.
- The API binds to `127.0.0.1`; LAN exposure is not enabled by the installer.
- The API key is generated with Python's OS-backed `secrets.token_hex(32)`, is never printed or passed in argv/environment, and is written only to mode-`0600` files.
- Existing `.env` content is preserved; the four API-server settings are updated atomically and duplicate definitions are removed.
- An existing checkout is updated only when its origin is `ethenotethan/harness`. Any other directory or Git origin fails closed.
- The app handoff accepts only schema version 1, a loopback `ws://` URL, a sufficiently long alphanumeric key, and a file inaccessible to group/other users.
- Existing or unreadable Keychain configuration always wins over an installer handoff.
- The handoff is not deleted until Portal successfully writes the URL and key into Keychain.
- The DMG packager rejects an app bundle that fails `codesign --verify --deep --strict`.

The handoff is intentionally a short-lived file rather than a URL scheme: placing the API key in a deep-link URL would expose it to command history and Launch Services metadata.

## Build

```bash
make installer
```

The artifact is written to `dist/Portal-Installer.dmg`. The local build proves packaging, but public releases still require a Developer ID signature, notarization, and stapling in release CI.

To package an already-built app directly:

```bash
./scripts/build-macos-installer.sh \
  --app /path/to/Portal.app \
  --output dist/Portal-Installer.dmg
```

## Verification

```bash
make installer-test
swift test --disable-sandbox --filter PortalBootstrapConfigurationTests
swift test --disable-sandbox --filter SettingsViewModelGatewayTests
hdiutil verify dist/Portal-Installer.dmg
```

Before calling the experience “two-minute setup,” test cold installs on clean Intel and Apple Silicon Macs and measure from opening the DMG through the first successful streamed response. Provider OAuth, Xcode Command Line Tools availability, network speed, Python/runtime downloads, and local-model downloads are outside the deterministic part of the current installer.

## Updating and removal

Rerun **Set Up Portal.command** from a newer DMG to update both Portal and the managed fork. The setup process preserves the profile and API key.

To remove the gateway cleanly before deleting files:

```bash
export HERMES_HOME="$HOME/Library/Application Support/Portal/hermes-home"
"$HOME/Library/Application Support/Portal/hermes-agent/venv/bin/hermes" gateway uninstall
```

Then remove `~/Applications/Portal.app` and `~/Library/Application Support/Portal` if the profile data is no longer needed.
